# Работа Product Owner (PO)

## 1. Описание проблемы

В учебных заведениях преподавателям нужно регулярно отмечать
посещаемость студентов. Если вести учёт вручную в журнале, это занимает
много времени. Также можно случайно допустить ошибку, потерять записи
или неправильно подсчитать количество пропусков.

Для решения этой проблемы разрабатывается приложение «Система контроля
посещаемости студентов». Оно позволит хранить список студентов, отмечать
их присутствие, отсутствие и опоздание, а также просматривать статистику
посещаемости.

Приложение будет работать на одном Android-устройстве и предназначено
для преподавателей и кураторов учебных групп.

## 2. User Stories и критерии приёмки

### US-01. Просмотр списка студентов

Как преподаватель, я хочу просматривать список студентов, чтобы быстро
находить нужного человека.

Критерии приёмки: - Отображается список добавленных студентов. - У
каждого студента указаны имя, фамилия и группа. - Список обновляется
после добавления или удаления студента.

### US-02. Добавление студента

Как преподаватель, я хочу добавлять новых студентов, чтобы вести
актуальный список группы.

Критерии приёмки: - Можно ввести имя, фамилию и учебную группу. - Нельзя
сохранить карточку с незаполненными обязательными полями. - После
сохранения студент появляется в списке.

### US-03. Удаление студента

Как преподаватель, я хочу удалять студентов из списка, чтобы в
приложении не было лишних записей.

Критерии приёмки: - Можно выбрать студента для удаления. - Перед
удалением появляется подтверждение. - После подтверждения студент
исчезает из списка.

### US-04. Отметка присутствия

Как преподаватель, я хочу отмечать присутствие студента на занятии,
чтобы вести точный учёт посещаемости.

Критерии приёмки: - Можно выбрать занятие и студента. - Можно установить
статус «Присутствовал». - Отметка сохраняется и отображается после
повторного запуска приложения.

### US-05. Отметка отсутствия

Как преподаватель, я хочу отмечать отсутствие студента на занятии, чтобы
учитывать его пропуски.

Критерии приёмки: - Можно выбрать студента и занятие. - Можно установить
статус «Отсутствовал». - Количество пропусков учитывается в статистике.

### US-06. Отметка опоздания

Как преподаватель, я хочу отмечать опоздание студента, чтобы учитывать
не только присутствие и отсутствие.

Критерии приёмки: - Можно установить статус «Опоздал». - Статус
сохраняется для выбранного занятия. - В истории посещаемости
отображается опоздание.

### US-07. Просмотр истории посещаемости

Как преподаватель, я хочу просматривать историю посещаемости студентов,
чтобы проверять их посещение за прошлые занятия.

Критерии приёмки: - Можно посмотреть записи о посещаемости. - У каждой
записи указаны дата, дисциплина и статус. - Записи отображаются для
нужного студента.

### US-08. Просмотр статистики

Как преподаватель, я хочу просматривать статистику посещаемости, чтобы
оценивать количество пропусков и посещённых занятий.

Критерии приёмки: - Отображается количество посещённых занятий. -
Отображается количество пропусков и опозданий. - Данные статистики
соответствуют сохранённым отметкам.

## 3. Определение экранов приложения

### 1. Главное меню

На главном экране отображается название приложения и три основные
кнопки: - «Студенты»; - «Отметить посещаемость»; - «Статистика».

С помощью этих кнопок преподаватель может перейти к нужному разделу.

### 2. Экран «Студенты»

На экране отображается список студентов. Также должны быть кнопки
добавления и удаления. В карточке студента указываются имя, фамилия и
учебная группа.

### 3. Экран «Отметка посещаемости»

На этом экране преподаватель выбирает занятие и студентов. Для каждого
студента можно установить один из трёх статусов: «Присутствовал»,
«Отсутствовал» или «Опоздал». После этого отметки сохраняются.

### 4. Экран «Статистика»

На экране отображается информация о посещаемости студентов. Можно
посмотреть количество посещённых занятий, пропусков и опозданий. Также
должна быть доступна история посещаемости.

## 4. Уточнение требований к модулю «Студенты» (Спринт 2)

### Поля карточки студента и правила проверки ввода
* **Фамилия (`lastName`):** обязательное поле (пробелы в начале и конце обрезаются).
* **Имя (`firstName`):** обязательное поле (пробелы в начале и конце обрезаются).
* **Учебная группа (`groupName`):** обязательное поле (пробелы в начале и конце обрезаются).
* **Пустой список:** если студентов нет, на экране выводится текст: *«Список студентов пока пуст»*.
* **Сообщения пользователю:**
    * При успешном добавлении: *«Студент добавлен»*
    * При ошибке пустых полей: *«Заполните все обязательные поля»*
    * При нажатии на удаление: диалоговое окно *«Удалить студента [Фамилия Имя]?»* с кнопками *«Удалить»* и *«Отмена»*
    * После удаления: *«Студент удалён»*

### US-09. Проверка ввода при добавлении студента
Как преподаватель, я хочу, чтобы приложение проверяло заполнение обязательных полей при добавлении студента, чтобы в список не попадали пустые записи или записи из пробелов.

Критерии приёмки:
- Если фамилия, имя или учебная группа не заполнены или состоят только из пробелов, студент не добавляется.
- На экране появляется понятное сообщение об ошибке.
- Лишние пробелы по краям строк автоматически удаляются перед сохранением.
