# Отчёт о выполнении Спринта 3 (Lead Developer)

**Проект:** «Система контроля посещаемости студентов» (`AttendanceControl`)  
**Роль:** Lead Developer (Участник В)  
**Цель спринта:** Реализовать создание и сохранение занятий, загрузку списка студентов выбранной группы, а также отметку и изменение статусов посещаемости в рамках текущего сеанса.

---

## 1. Выполненные задачи

1. **Проектирование моделей данных и временного хранилища (`data`):**
    * Созданы классы данных `Lesson` (идентификатор, учебная группа, дата, дисциплина) и `Attendance` (идентификатор студента, дата занятия, дисциплина, статус посещаемости).
    * Реализован синглтон-объект `AttendanceRepository`, обеспечивающий хранение списка занятий и отметок в оперативной памяти, а также интеграцию с `StudentRepository` из Спринта 2 для динамического получения списка учебных групп и фильтрации студентов по выбранной группе.
    * Реализована защита от дублирования занятий (по связке группа + дата + дисциплина) и правило одной итоговой отметки на студента за конкретное занятие (при повторном сохранении предыдущая запись перезаписывается).
2. **Разработка интерфейса экрана занятий и отметки посещаемости (`res/layout`):**
    * Оформлена разметка `activity_attendance.xml` с разделением на блок создания нового занятия (выбор группы через `Spinner`, выбор даты через `DatePickerDialog`, ввод дисциплины), выпадающий список ранее сохранённых занятий, область отображения списка студентов и кнопку сохранения.
    * Создана разметка элемента списка `item_attendance_student.xml` с выводом ФИО студента и блоком переключателей `RadioGroup` (`«Присутствовал»`, `«Отсутствовал»`, `«Опоздал»`).
    * Добавлен атрибут `android:fitsSystemWindows="true"` на экранах `activity_attendance.xml` и `activity_students.xml` для корректного отступа интерфейса от системного статус-бара.
3. **Реализация логики экрана и адаптера списка (`ui`):**
    * Разработан адаптер `AttendanceAdapter` для `RecyclerView`, управляющий выбором и переключением статусов студентов в памяти до момента окончательного сохранения и исключающий сброс состояний при прокрутке списка.
    * Реализована логика `AttendanceActivity`: валидация полей при создании занятия, переключение между несколькими сохранёнными занятиями, подгрузка ранее выставленных отметок для редактирования и отображение информационной заглушки с блокировкой кнопки сохранения при пустом списке студентов.
4. **Интеграция и работа с Git / Мос:**
    * Разработка велась в отдельной ветке `feature/attendance-screen` с осмысленными коммитами по каждому этапу.
    * Изменения объединены с основной веткой `main` после проверки сборки и совместного прогона сценариев с QA / DevOps и Product Owner.

---

## 2. Реализованные компоненты и технические решения

| Компонент / Файл | Пакет / Расположение | Назначение и принятое техническое решение |
| :--- | :--- | :--- |
| **`Lesson.kt`**, **`Attendance.kt`** | `com.college.attendance.data` | Модели данных занятия и отметки посещаемости. Разделены на две сущности, чтобы преподаватель мог заранее создавать несколько занятий и переключаться между ними. |
| **`AttendanceRepository.kt`** | `com.college.attendance.data` | Временное хранилище (In-Memory) для Спринта 3. Читает группы и студентов напрямую из `StudentRepository` (Спринт 2), что исключает дублирование списков студентов в памяти. |

| **`AttendanceActivity.kt`** | `com.college.attendance.ui` | Управляет созданием занятий, выбором даты через `DatePickerDialog`, переключением между сохранёнными занятиями и перезаписью итоговых отметок. |
| **`activity_attendance.xml`**, **`item_attendance_student.xml`** | `res/layout` | XML-разметка экрана занятий и карточки студента. При пустой группе или отсутствии занятий `RecyclerView` скрывается, а кнопка сохранения переводится в состояние `enabled = false`. |
