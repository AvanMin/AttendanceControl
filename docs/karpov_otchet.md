## 3. Технические решения

- **Разделение на слои.** Модель, проверка и хранение находятся в пакете `data`, работа с экраном — в пакете `ui`. Activity не содержит правил валидации, поэтому их можно проверять JUnit-тестами без эмулятора.
- **Репозиторий как единая точка доступа к данным.** При переходе на Room в спринте 4 достаточно заменить реализацию методов `StudentRepository` на вызовы DAO, экран почти не изменится.
- **ListAdapter и DiffUtil.** Список обновляется через `submitList`, без ручного вызова `notifyDataSetChanged`.
- **Нормализация ввода.** Перед проверкой и сохранением значения обрезаются и очищаются от повторяющихся пробелов, поэтому «Иванов » и «иванов» считаются одной записью.
- **Ошибки у полей.** Для сообщений используется `EditText.error`, фокус переходит на первое некорректное поле.
- **Строки в ресурсах.** Все тексты вынесены в `strings_students.xml`, в коде нет жёстко заданных сообщений.

## 4. Проблемы и решения

| Проблема | Решение |
| --- | --- |
| Ввод из одних пробелов проходил проверку на пустоту | Значение нормализуется (`trim`) до проверки |
| Имя из одного дефиса считалось допустимым | Добавлено требование хотя бы одной буквы |
| Один и тот же студент добавлялся повторно с другим регистром | Сравнение по трём полям без учёта регистра |
| Тёзки из разных групп не должны считаться дубликатами | В сравнение включено название группы |
