# Индивидуальный отчёт Lead Developer

**Проект:** «Система контроля посещаемости студентов»  
**Спринт 2:** Студенты и учебные группы  
**Роль в спринте:** Lead Developer (LD)  
**Студент:** Карпов Илья

## 1. Цель спринта

Реализовать добавление, просмотр и удаление студентов с проверкой введённых данных. Данные на этом этапе хранятся во временной коллекции в памяти; подключение Room запланировано на спринт 4.

## 2. Выполненные задачи

| № | Задача | Результат |
| --- | --- | --- |
| 1 | Создать модель студента | Класс `Student` (data class) с полями id, firstName, lastName, groupName в пакете `data` |
| 2 | Реализовать проверку ввода | Класс `StudentValidator`: отклоняет пустые поля и поля из одних пробелов, цифры и спецсимволы в имени, недопустимые символы в названии группы, слишком длинные значения; убирает лишние пробелы |
| 3 | Реализовать хранение во временной коллекции | Объект `StudentRepository`: добавление, удаление, получение списка, защита от дубликатов без учёта регистра, сортировка по группе и фамилии |
| 4 | Создать форму добавления | Экран `activity_students.xml` с тремя полями EditText и кнопкой «Добавить студента»; ошибки показываются у конкретного поля |
| 5 | Вывести список студентов | `RecyclerView` с адаптером `StudentAdapter` на базе `ListAdapter` и `DiffUtil`; счётчик студентов; сообщение при пустом списке |
| 6 | Добавить удаление с подтверждением | Диалог `AlertDialog` с кнопками «Удалить» и «Отмена» |
| 7 | Написать модульные тесты | `StudentValidatorTest` (9 тестов) и `StudentRepositoryTest` (7 тестов) |

## 3. Технические решения

- **Разделение на слои.** Модель, проверка и хранение находятся в пакете `data`, работа с экраном — в пакете `ui`. Activity не содержит правил валидации, поэтому их можно проверять JUnit-тестами без эмулятора.
- **Репозиторий как единая точка доступа к данным.** При переходе на Room в спринте 4 достаточно заменить реализацию методов `StudentRepository` на вызовы DAO, экран почти не изменится.
- **ListAdapter и DiffUtil.** Список обновляется через `submitList`, без ручного вызова `notifyDataSetChanged`.
- **Нормализация ввода.** Перед проверкой и сохранением значения обрезаются и очищаются от повторяющихся пробелов, поэтому «Иванов » и «иванов» считаются одной записью.
- **Ошибки у полей.** Для сообщений используется `EditText.error`, фокус переходит на первое некорректное поле.
- **Строки в ресурсах.** Все тексты вынесены в `strings_students.xml`, в коде нет жёстко заданных сообщений.

## 4. Проблемы и решения

| Проблема | Решение |
| --- | --- |
| Ввод из одних пробелов проходил проверку на пустоту | Значение нормализуется (`trim`) до проверки |
| Имя из одного дефиса считалось допустимым | Добавлено требование хотя бы одной буквы |
| Один и тот же студент добавлялся повторно с другим регистром | Сравнение по трём полям без учёта регистра |
| Тёзки из разных групп не должны считаться дубликатами | В сравнение включено название группы |

## 6. Работа в команде и Git

Работа выполнялась в отдельной ветке `feature/add-student`. Предлагаемые коммиты:

1. «Добавлена модель Student и валидатор ввода»
2. «Добавлен StudentRepository с хранением во временной коллекции»

4. «Добавлено удаление студента с подтверждением»
5. «Добавлены модульные тесты валидатора и репозитория»

Перед объединением с `main` код передаётся QA / DevOps для проверки сборки и прогона тест-кейсов.
